# План: доделать весь roadmap Yue Studio (v2 + v3, кроме SD Studio)

Объём: пиано-ролл + фрагментное превью, инструментальная стойка + овердаб, профиль из корпуса, Remix (SheetSage2), demucs-стемы. Интеграцию с SD Studio исключили (её в плане не было).

Ключевые технические факты (проверено):
- yue2 0.1.6 поддерживает поэтапную генерацию: `plan() → generate_semantic() → synthesize() → decode()` (чанковый tiled decode). Артефакты джобы уже содержат `latent.npy`, `semantic.npy`, `prefix.npy`, `score.abc`.
- SheetSage2 (`m-a-p/SheetSage2`, HF, 57M параметров): аудио → score.abc + MIDI + события; требует torch/torchaudio 2.8, FFmpeg 6.1 (shared libs), репозиторий gated (нужен HF-токен).
- demucs не установлен; faster-whisper уже есть в отдельном `~/whisper-venv` на 184. GPU сейчас свободен.

## Этап 0 — установка и смоук-тесты на 184
1. Проверить HF-токен на 184 (`~/yue/.venv`, HF_HOME=/mnt/e/AI/hf-cache). Если нет — запросить у пользователя (gated-репо).
2. `pip install` SheetSage2 (requirements из репо) в `~/yue/.venv`; FFmpeg 6.1 shared libs: попробовать apt (если есть sudo) либо pip-пакет/статик-сборку; если FFmpeg не решается — фолбэк: подавать в SheetSage2 уже декодированный waveform через torchaudio/soundfile (его API это умеет), FFmpeg не нужен.
3. `pip install demucs` в тот же venv.
4. Смоук: транскрипция одного трека SheetSage2 → ABC; разделение одного трека demucs → 4 стема. Проверить VRAM-сосуществование с резидентной YuE2 (обе тяжёлые операции — под общим `_pipe_lock`).

## Этап 1 — Remix: транскрипция трека → ABC → кавер (v3)
Воркер:
- `POST /transcribe` (аудио-байты + X-Filename, синхронно под `_pipe_lock`): SheetSage2 → сохранить в `data/transcribes/<id>/` (score.abc, events.json, midi) → `{abc, id}`. Ленивый синглтон модели как у YuE (57M — в памяти можно держать).
Фронт:
- В модалке плана новый режим «Из трека»: загрузка аудио → полученный ABC в тот же редактор → рендер кавера с новым стилем/текстом (существующий механизм req_abc).

## Этап 2 — пиано-ролл + фрагментное превью (v2)
Воркер:
- `GET /jobs/{id}/score` — парсер score.abc (свой парсер на Python, без music21): такты × партии/голоса, аккорды, секции, длительность в секундах (по темпу ABC) → JSON-расклад; плюс RMS-громкость по секциям из audio.flac (librosa, кэш в score.json).
- `POST /jobs/{id}/preview {from_sec, to_sec}` — превью фрагмента: загрузить `latent.npy` джобы, срезать латенты по времени (25 Hz semantic / чанк-сетка yue2), `pipe.decode()` только этого куска → `preview-<from>-<to>.flac`. Дёшево (только VAE-decode, без AR-генерации). Предел честно фиксируем: превью работает для «послушать кусок», правка середины всё равно = пересбор.
Фронт:
- Компонент-таймлайн под карточкой джобы: сетка такт × инструмент (▓/▒/░ по плотности нот), аккорды, секции, RMS-бар; выделение диапазона мышью → «Превью фрагмента» (кнопка играет через /listen или сохраняет).

## Этап 3 — инструментальная стойка + овердаб (v2)
Фронт:
- `frontend/src/rack.js` — библиотека инструментов по группам (ритм-секция/гитары/клавиши/народные/электроника/спецслои), карточка = формулировка слота + варианты примочки (clean/fuzz/tremolo/phaser/wah/reverb); выбор разворачивается в текст стиля автоматически, стойка = массив `{instrument, effect}`, входит в параметры джобы/пресета.
- Слоты формы получают поле «стойка» рядом с существующими.
Воркер:
- `POST /jobs/{id}/overdub {style, lyrics?}` — овердаб: рендер новой партии по `request.abc`/`score.abc` исходной джобы (механизм req_abc уже есть) → сведение с исходным audio.flac в numpy (выравнивание длины, микс, лёгкий кроссфейд) → `overdub.flac` + metrics. В UI кнопка на карточке «Овердаб» с выбором стиля партии.

## Этап 4 — профиль из корпуса (v2)
Воркер:
- `POST /corpus {name}` + `POST /corpus/{id}/tracks` (аудио-байты, 3–10 треков) + `GET /corpus/{id}`.
- Пайплайн по трекам: SheetSage2 → статистика тональностей/прогрессий/темпов/структур → ABC-шаблон; dsp.py → усреднённый DSP-паспорт; текст: быстрее-whisper (subprocess из `~/whisper-venv`) → приёмы текста → стилевое описание через Ollama-копайтер (уже есть).
- Итог: JSON-профиль (style-строка, slots, ABC-шаблон, DSP-паспорт) → в UI кнопка «Профиль → пресет».
Фронт:
- Раздел «Профили»: создание, загрузка треков, прогресс, просмотр результата, импорт в пресеты/форму.

## Этап 5 — demucs-стемы (v3)
Воркер:
- `POST /jobs/{id}/stems` — demucs (htdemucs, под `_pipe_lock`, lazy-load/unload чтобы не держать VRAM рядом с YuE) → `stems/{drums,bass,vocals,other}.flac` + metrics на каждый; `GET /jobs/{id}/stems`.
- Стемы доступны в /listen и как источник DSP-вариантов и для профиля корпуса.
Фронт: кнопка «Стемы» на карточке, список стемов с прослушиванием/сохранением.

## Этап 6 — сборка и документация
- `deploy.sh worker` обновить (если появятся новые файлы: sheetsage.py, corpus.py, stems.py — разнести yue_worker.py на модули).
- README: новые эндпоинты, ограничения (предел точечной правки, VRAM, лицензия CC BY-NC), обновлённый roadmap-статус.
- `./deploy.sh worker` + смоук всех новых эндпоинтов на 184, `./deploy.sh build`.

## Риски
- SheetSage2 gated: без HF-токена этапы 1 и 4 блокируются — тогда фолбэк на librosa-скелет (тональность/темп/структура) и явное сообщение пользователю.
- FFmpeg 6.1 shared libs на 184: фолбэк — подача waveform напрямую (минуя файловый вход).
- VRAM 16 ГБ: YuE2 резидентна (7.7 ГБ); demucs и SheetSage2 — только под `_pipe_lock` с выгрузкой; Ollama-копайтер уже с `keep_alive: 0`.
- Овердаб — не настоящее сведение стемов (YuE2 стемов не даёт): честно пометим в UI как «генерация партии поверх + микс».

Порядок выполнения: 0 → 1 → 2 → 3 → 4 → 5 → 6, с деплоем и смоук-тестами после каждого этапа (коммит на каждый этап).
